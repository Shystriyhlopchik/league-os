# Пакетная коррекция календаря

Страница `/dashboard/calendar?tournamentId=ID` заменена табличным редактором. Код развёртывается совместно на frontend и backend; новой миграции нет. Рабочая БД при разработке не менялась.

## Работа организатора

1. Выбрать турнир, тур, при необходимости этап и группу. Навигация и общее сохранение закреплены. Фильтры и переход к соседнему туру не удаляют черновик.
2. Изменять поля строк: тур, дату, время, площадку, длительность слота либо явно отметить «Дата уточняется».
3. Для массового редактирования отметить строки. Доступны общая дата/площадка, последовательная расстановка с выбранного времени, сдвиг на указанное число минут, перенос в тур. Операции применяются ко всем выделенным строкам, включая скрытые фильтрами; их количество показано отдельно.
4. Указать общую причину, нажать «Проверить и сохранить». Исправить все показанные конфликты либо проверить сравнение «Было → станет». Подтвердить изменения.

Перенос в другой тур не меняет дату. Строка остаётся видна в исходном и целевом турах до сохранения, с меткой нового тура. Доступен только существующий тур той же группы/этапа. У команды не должно оказаться двух встреч в одном туре; связанные переносы нужно внести одним пакетом. Номера раундов плей-офф менять нельзя, даты — можно при соблюдении зависимостей сетки.

Сохранённая длительность отображается как фактический занятый интервал. При первом редактировании строки с первоначальной ревизией применяется значение из правил (таймы × минуты + 15). Ранее явно сохранённый слот не заменяется. До редактирования чужие занятые интервалы не сокращаются незаметно. Длительность можно изменить вручную; для последовательной расстановки используется длительность каждой выбранной игры.

## Гарантии сервера

- `POST /tournaments/:id/calendar-management/preview` проверяет пакет, ничего не записывая.
- `PATCH /tournaments/:id/calendar-management` повторяет проверку и сохраняет весь пакет в одной транзакции. Нельзя реализовывать это несколькими одиночными PATCH на клиенте.
- Обе операции требуют JWT и права EDIT конкретного турнира.
- Проверяется итоговое состояние: обмен занятыми слотами допустим, временные пересечения в черновике не мешают вводу. Учитываются неизменённые матчи, бронирования площадок/команд других турниров, соседние непересекающиеся слоты, длительность и переход через полночь.
- Транзакция использует тот же порядок блокировок, что одиночные переносы и обслуживание матча: турнир → строки матчей → глобальная блокировка бронирования. Предпросмотр не резервирует слот; окончательное сохранение снова проверяет его доступность.
- Каждая строка передаёт `expectedRevision`. Подтверждение также передаёт хеш проверенного состояния `expectedVersion`. Новая запись другого организатора, начало матча или внешнее бронирование не перезаписываются молча. При конфликте весь пакет отклоняется.
- `requestId` и хеш содержимого сохраняются в существующем JSON-журнале расписания. Повтор принятого пакета, в том числе после дальнейших исправлений, не применяет его повторно. Другие данные/автор с тем же UUID отклоняются. Идентификатор сохраняется в открытом редакторе при потере ответа и повторной отправке неизменённого пакета.
- Начатые, завершённые и отменённые матчи не изменяются. Пары, группа, этап, результаты и ID сохраняются. Изменяются только расписание и разрешённый номер тура.
- Подтверждение составов судьёй сбрасывается только у действительно изменённых матчей; игроки и сами составы не удаляются.
- Блокировка заявок, достигнутая до изменения либо в итоговом расписании, фиксируется. Уже наступивший запрет не отменяется переносом четвёртого тура. Изменение будущей даты ограничения показано в предупреждении до подтверждения.

## Обратная связь и ограничения

Ошибки появляются общим списком и у соответствующих полей. «К матчу» снимает мешающие фильтры и переводит к строке. Результат проверки/сохранения прокручивается в видимую область. После успешной записи и неуспешного обновления списка показывается отдельное предупреждение; редактирование блокируется до загрузки актуального календаря.

Черновик хранится в памяти открытой страницы. Есть предупреждение перед выходом/перезагрузкой и скачивание резервного JSON. Автовосстановление после закрытия браузера и импорт этого JSON не добавлялись. После перезагрузки нужно сначала загрузить серверный календарь: UUID открытого редактора не восстанавливается из резервного файла автоматически.

Старый одиночный endpoint оставлен для совместимости. Прямые SQL-правки и сторонние механизмы записи обходят ревизии/журнал. Уже открытые публичные страницы получают изменения при следующем запросе; рассылка уведомлений капитанам не добавлялась.

## Проверки

- Модульные проверки итоговых пересечений, переноса туров, последовательности плей-офф, DTO и прав доступа.
- `match-continuity.integration.spec.ts`: обмен слотов, предпросмотр без записи, идемпотентный повтор, перенос между турами, конфликты ревизий, начало игры после проверки, внешняя бронь, параллельное сохранение, полный откат при сбое второй записи, блокировка заявок. Запускается только на явно проверенной одноразовой PostgreSQL `127.0.0.1:5547/league_os_continuity_check`.
- Браузерные тесты компонента: несколько туров в одном пакете, валидация, сравнение перед отправкой, повтор UUID, ошибки/задержки сети, массовая расстановка и переход через полночь, защита черновика и отказ обновления после успешной записи.
- Визуальная проверка production-сборки на подставных API-ответах, без обращения к рабочему backend: редактирование двух строк → один предпросмотр; desktop и мобильная компоновка.
