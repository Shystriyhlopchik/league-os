# Видео лиги

## Работа организатора

Откройте **Личный кабинет → Видео лиги** (`/dashboard/videos`). Раздел доступен
владельцам и администраторам сообщества, а также суперадминистратору платформы.
Одна глобальная роль `admin` без прав в сообществе доступа не даёт.
Флаг конструктора турниров не требуется.

1. Выберите сообщество, нажмите **Добавить видео**.
2. Введите название и ссылку на отдельный ролик ВК. Поддерживаются HTTPS-ссылки
   вида `https://vkvideo.ru/video-123_456`, аналогичные адреса `vk.com`/`vk.ru`
   и код iframe из меню ВК **Поделиться → Экспортировать**.
   Плейлисты и клипы не поддерживаются. Для роликов, которым нужен `hash`,
   используйте именно код экспорта: он сохраняет необходимый параметр.
3. Загрузите обложку PNG/JPEG/WebP до 5 МБ. Рекомендуемый размер — 1280×720.
   Для черновика обложку можно добавить позже, для публикации она обязательна.
4. При необходимости выберите турнир и матч этого сообщества.
5. Сохраните черновик и нажмите **Плеер** в списке. Проверьте, что в ВК
   разрешено встраивание и просмотр доступен посетителям без авторизации.
6. Нажмите **Изменить**, выберите **Опубликовано**, включите **Показывать на
   главной**, сохраните. Обновите главную страницу.

На главной показаны до восьми опубликованных видео сообщества по умолчанию
(`communities."isDefault" = true`). Выбор активного турнира на это не влияет.
При добавлении других сообществ public API принимает `communityId`; привязка
отдельных доменов к сообществам в эту задачу не входит.

Порядок: меньшее число раньше; при равенстве — более новая дата публикации,
затем больший ID. Лимит восьми публикаций на главной защищён на сервере, в том
числе при одновременной работе администраторов. Чтобы заменить ролик, сначала
снимите старый с главной. Более восьми черновиков хранить можно.

Для снятия с публикации выберите **Черновик** и сохраните. Галочка главной
независима от состояния публикации. Видео, не отмеченное для главной,
видно на отдельной публичной странице **Медиа → Видео** (`/videos`).
**В архив** скрывает запись, но не удаляет ролик из ВК и файл обложки.
Восстановление архивной записи через интерфейс пока не предусмотрено.

## Публичная страница видео

`/videos` показывает все опубликованные и не архивированные ролики активного
сообщества по умолчанию, независимо от галочки «Показывать на главной».
Новые публикации идут первыми; при одинаковой дате — запись с большим ID.
Страница загружает по 12 карточек с кнопками «Назад» и «Далее».
Черновики и архивные записи посетителям недоступны. Для пустой медиатеки,
загрузки и ошибки предусмотрены отдельные сообщения; неудачный запрос можно повторить.
На главной по-прежнему остаётся подборка до восьми роликов и ссылка «Все видео».

API главной не изменён: `GET /api/videos`. Полная медиатека доступна через
`GET /api/videos/catalog?page=1&limit=12` (максимальный `limit` — 50).
Оба публичных API возвращают только название, обложку, адрес плеера, дату
публикации, ID видео и привязки к турниру/матчу. Авторизация для просмотра не нужна.
Эта страница не требует дополнительной миграции сверх существующей таблицы видео.

Публичная навигация сгруппирована одинаково на компьютере и телефоне:

- **Турнир:** матчи, таблица, чемпион, регламент соревнований.
- **Участники:** команды, игроки, рейтинг.
- **Медиа:** новости, видео.

«Главная» и «Кабинет» остаются отдельными пунктами. На компьютере группы
раскрываются по нажатию, доступны с клавиатуры и закрываются по Escape,
уходу фокуса, клику снаружи или переходу. На телефоне внутри общего меню
все группы сразу раскрыты — дополнительное нажатие для каждой не нужно.

## Поведение плеера

На странице изначально нет iframe: загружаются только локальные обложки.
Клик открывает один плеер в диалоге, не меняя адрес страницы. Закрытие кнопкой,
Escape или нажатием на фон удаляет iframe и останавливает воспроизведение.
Фокус возвращается к карточке. В полноэкранном режиме первый Escape может
сначала закрыть полноэкранный режим самого плеера.

Код HTML не исполняется и не сохраняется: сервер извлекает только разрешённые
идентификаторы и `hash`, формирует адрес `https://vkvideo.ru/video_ext.php`.
Произвольные домены, SVG-обложки и пути вне `/uploads/videos/` не принимаются.
Сервер не обращается по введённым URL, токен ВК не нужен.

Содержимое плеера (реклама, ссылки ВК, ограничения доступа) контролируется ВК.
Сайт не может убрать их или гарантировать доступность закрытого/удалённого
видео. Автоматическое получение названия, обложки и синхронизация с каналом
не реализованы.

## Миграция и запуск

Новая таблица создаётся миграцией `CommunityVideos1792886400000`.
До применения миграции API видео работать не будет; публикации не добавляются
автоматически. Резервируйте production-БД перед обновлением.

В production используйте штатный сервис миграций и **то же имя Compose-проекта**,
что у действующего стека:

```bash
cd /home/arman/league-os
docker compose -p league-os-prod --env-file .env -f infrastructure/docker/docker-compose.prod.yml build migrations backend frontend
docker compose -p league-os-prod --env-file .env -f infrastructure/docker/docker-compose.prod.yml run --rm migrations
docker compose -p league-os-prod --env-file .env -f infrastructure/docker/docker-compose.prod.yml up -d --no-deps backend frontend
```

Если миграции завершились ошибкой, остановитесь, не выполняйте последний шаг.
Не запускайте `down -v`: это удалит тома данных. Иные Compose-проекты не затрагивайте.
Используется существующее хранилище `uploads` (в production — `uploads_data`),
новых SMTP/VK-переменных окружения нет.

Локально примените миграции штатной командой backend `npm run migration:run`
в окружении с настройками **локальной** БД (или внутри уже используемого
dev-контейнера backend). Не копируйте production-реквизиты. Frontend обычно
подхватывает код автоматически; backend должен работать с новой сборкой.

## Проверка интерфейса

- Гость и обычный участник не имеют доступа к кабинету видео.
- Администратор не может менять видео другого сообщества даже подстановкой ID.
- Пустая медиатека скрывает блок на главной; ошибка API предлагает повторить запрос.
- «Все видео» и «Медиа → Видео» открывают `/videos`; пустая страница не исчезает.
- Ролик без галочки главной виден на `/videos`, но отсутствует на главной.
- Более 12 публикаций разбиваются на страницы; при загрузке кнопки недоступны.
- Пустая форма показывает ошибки и не отправляет запрос.
- Некорректная ссылка, чужой домен, клип и поддельное изображение отклоняются.
- Черновик не виден гостю, опубликованный ролик с обложкой появляется после обновления.
- Девятое видео на главной не публикуется: показано понятное сообщение.
- Замена порядка, обложки и названия видна после сохранения/обновления.
- Удаление из публикаций и архивирование убирают карточку.
- Клик по карточке не меняет URL, закрытие диалога останавливает звук.
- Проверить клавиатуру (Tab, Enter, Escape), возврат фокуса и ширину 375/768/1440 px.
- Проверить реальный публичный ролик в браузере без входа в ВК.

Автоматические проверки:

```bash
# Из league-os-backend
npm test -- --runInBand --testPathPatterns=modules/videos

# Из league-os-frontend
npm test -- --watch=false --browsers=ChromeHeadless
```

Для браузерного smoke-теста без доступа к БД предусмотрен
`league-os-frontend/scripts/video-ui-smoke.cjs`. Он поднимает временный HTTP-сервер
из `dist/arman/browser`, подменяет **все** API-запросы тестовыми ответами и
не обращается в ВК. Требуются доступный Node-модуль `playwright` и установленный
Microsoft Edge. После `npm run build` запустите из frontend:

```bash
node scripts/video-ui-smoke.cjs
```

Результат — `PASS` и скриншоты в игнорируемом Git каталоге `test-results/videos`.
Проверяется сетка на 375/768/1440 px, отсутствие горизонтальной прокрутки,
открытие/закрытие одного iframe, Escape, возврат фокуса, валидация и сохранение
черновика в памяти теста. Это не заменяет проверку миграции и воспроизведения
реального ролика в ВК.
